browser-profile-router
とは何か

macOS で URL を、ユーザーが指定したブラウザまたは Chrome プロファイルへ明示的に開くためのルーターです。便利さよりも、既存のブラウザ利用環境を壊さないことを最初の設計条件にしています。

目的 機能一覧 動作の流れ 安全境界 現在の状態 根拠資料

ひとことで言うと

「この URL は、どの作業用プロファイルで開くか」を人が選べるようにする macOS アプリの設計です。 Chrome には --profile-directory を明示して起動し、それ以外のブラウザは汎用的にアプリを指定して開く、という小さく安全な責務に絞っています。

設計を支える 3 つの層

1. BrowserTarget

表示名・対象アプリ・起動方法を持つ設定モデルです。通常起動と「Chrome + プロファイルディレクトリ」を分けて表現します。

2. LaunchCommandBuilder

入力 URL と対象設定から、実行ファイルと引数を組み立てます。実行前に導出されたコマンドを確認できることが重要です。

3. SwiftUI / TargetStore

対象の編集・選択・起動を扱う UI と、アプリ自身の設定だけを保存する領域です。Chrome の設定領域は書き換えません。

設計上の機能一覧

保存済みターゲットの選択

仕事用・個人用など、名前を付けたブラウザ起動先を選びます。各ターゲットには対象アプリと起動方式を持たせます。

Chrome プロファイル指定

Chrome を開く際、--profile-directory でプロファイルディレクトリを明示します。別プロファイルの Chrome が使用中でも検証可能な設計です。

汎用ブラウザ起動

Chrome 以外は、選択したブラウザアプリへ URL を渡す汎用起動を行います。プロファイル機能があるとは扱いません。

URL・設定値の検証

URL の形式とプロファイルディレクトリを起動前に検証し、不正な入力で意図しない起動が起きることを防ぎます。

起動コマンドのプレビュー

実行前に、使う実行ファイルと引数を確認できます。どのプロファイルで何を開くかを追跡しやすくします。

アプリ専用設定の保存

ターゲット設定はアプリの設定領域に保存します。Chrome のプロファイルデータ・Cookie・Sync 設定を変更しません。

URL を開くまでの流れ

01 / ENTER

URL を入力

ユーザーが URL を入力し、保存済みの対象を選びます。

02 / VALIDATE

入力を検証

不正な URL や空のプロファイルディレクトリを、起動前に拒否します。

03 / PREVIEW

コマンドを確認

どの実行ファイルと引数が使われるかを、実行可能な形で表示します。

04 / OPEN

明示的に起動

Chrome は選択プロファイル付きで、他ブラウザは汎用起動で URL を開きます。

安全のために、すること／しないこと

すること

  • 名前付きの仕事用・個人用ターゲットを設定する
  • Chrome の --profile-directory を明示して URL を開く
  • アプリ専用の設定を ~/.config/browser-profile-router/config.yaml（または XDG_CONFIG_HOME）に保存する
  • 必要に応じて Chrome のメタデータを読み取り専用で参照する

しないこと

  • アプリ自身の判断で macOS のデフォルトブラウザを変更する
  • Chrome のプロファイル、Cookie、Sync、Local State を編集する
  • 明示的な YAML ルールなしに、URL の分類やターゲット選択を自動化する
  • Chrome 以外に、根拠のないプロファイル指定機能を追加する

インストール時には LaunchServices へアプリを登録しますが、デフォルトブラウザへの設定はユーザーがシステム設定から明示的に行います。YAML ルールに一致する URL だけは、設定済みターゲットを自動選択します。
